# v1.10.0 — The Numbers Audit (RELEASE_PROTOCOL §4.8)

Six questions, in writing, for every number this release adds or changes. This is the gate that
exists for bug class #1: *a number that is wrong in the direction that reassures the learner*, and
its v0.7 corollary, *a number whose LABEL is wrong is a wrong number*.

**The numbers under audit are deliberately few, and that is the first finding.**

| new figure | where | what it is |
|---|---|---|
| `doctor.probe_gaps` | `doctor` JSON | a **list** of {topic, node, criterion, kind, note} — not a rate |
| "N node(s) carry a rubric criterion…" | `doctor.notes` | a **count of distinct nodes** per topic |
| `receipts_under_previous` | `edit-node` output, `node.revised[]` | a **count of receipts** written before a contract repair |
| `probe_gap` | on a receipt | a **list of 1-based criterion indices** — not a score |

**No rate ships in this release, on purpose.** The obvious feature here was a "curriculum health"
percentage — *"87% of your rubrics are answerable"* — and it was not built. A rate needs a
denominator that survives Q3, and every candidate denominator (nodes? criteria? graded nodes?)
tells a different story about the same graph. More decisively, the thing being counted is produced
by a **heuristic with a known miss rate** (below), so a percentage would launder an 80%-precision
regex into a number people quote. Lists and counts-of-things-you-can-go-look-at do not have that
failure mode: every entry names the exact node and criterion, so the reader can check it.

---

## Q1 · Is it cross-consistent with every other number the engine computes?

**Yes, and it was run side by side rather than reasoned about.** On the author's real state
(three topics, 60 non-capstone nodes):

```
doctor.probe_gaps                      -> 21 entries across 3 topics
doctor.notes (per topic)               -> llm-training-stages 4 · scalable-system-design 9 · transformers-ffn 8   (= 21)
independent scan of graphs/*.json      -> 21 nodes flagged, same node ids
add-topic warnings on the same payload -> same criterion numbers
```

The per-topic counts sum to the list length because the narrator counts **distinct nodes** and no
node in this state carries two flagged criteria. That is a coincidence of this data, not an
invariant — so the note says *"N node(s)"* and the list stays the authority. Two counts that could
diverge do not share a name (Q6 rule 1).

`probe_gaps` deliberately does **not** appear in `stats`, `retention`, `adherence` or the dashboard.
It describes the *curriculum*, not the learner, and mixing it into the learner's telemetry is how
"your recall is 62%" and "your rubrics are broken" become one confusable figure.

## Q2 · Which direction does it fail in?

**Both figures fail PESSIMISTICALLY, which is the tolerable direction — and this was designed for,
not discovered.**

- A **false positive** in the scan says a node is defective when it is fine. Cost: the author reads
  a criterion and disagrees. Nothing is deleted, no grade moves, no schedule changes.
- A **false negative** says nothing. The status quo before this release was 100% false negatives,
  so the check cannot be worse than not having it.
- `receipts_under_previous` counts receipts that exist on disk; it cannot overcount, and
  undercounting would only under-state a caveat that is already conservative.

**The optimistic failure mode was designed out of the system, in the one place it could have
appeared.** The tempting version of this feature has the assessor *forgive* a criterion the probe
never asked for — which would raise `partial` to `recalled`, raise `retention`, and hide a
curriculum defect inside a better-looking score. That is bug class #1 exactly. `probe_gap` therefore
**does not move the grade**, by explicit instruction in the assessor spec and by a selftest that
fails if a graded item's rating changes when the field is present.

## Q3 · What is its denominator, and does it say so?

**There is no denominator, because there is no rate — see the header.** The two counts name their
own unit in the string: *"N node(s)"*, *"N receipt(s) … graded against the PREVIOUS contract"*.

The one place a denominator lurks is the **39% quoted in the CHANGELOG and the architect spec**.
Its denominator is stated everywhere it appears: *62 architect-authored nodes across three topics,
one account, one model family*. It is labelled as evidence that the defect is systematic and shaped
— **not** as a population rate, and the CHANGELOG says so in its own paragraph. If it were shipped
as a computed figure it would need a floor and a caveat; it is a one-off measurement in prose, and
it is fenced as one.

## Q4 · Does anything actually READ it — and does EVERY SURFACE read it?

This is the question the design was built around, because a probe/rubric mismatch is exactly the
kind of finding that dies in a nested key.

| surface | reads it | as what |
|---|---|---|
| `add-topic` | yes | a `warnings` entry naming the node **and** criterion number, at authoring time |
| `edit-node` | yes | re-runs the scan after the edit and returns what survives |
| `doctor` | yes | `probe_gaps` (uncapped) **plus** one `notes` line per topic that **names the repair command** |
| `/learn` | yes | relays `probe_gap` to the learner as *the card's fault*, then repairs in-session |
| `/review` | yes | runs the check by hand before marking any criterion missed |
| assessor | yes | emits `probe_gap` |

**Nothing is capped, so a count cannot flatter by truncation.** The `notes` line exists precisely
because a structured list with no narrator is the guard-nobody-reads class; it carries the fix, not
just the number.

**The dashboard deliberately does not render it**, and that is a considered exclusion rather than an
oversight: the HTML dashboard is the learner's telemetry, and a curriculum-authoring defect shown
beside retention bars invites the reading *"my recall number is bad because the cards are bad"* —
which would be an excuse manufactured by the tool. The finding belongs where the repair is
(`/learn`, `/review`, `doctor`), and every one of those surfaces carries it. **`doctor` is checked
for the failure string by a selftest**, not merely for the field.

## Q5 · Can it be reached from the CLI in a way the skills never take?

Yes, and both paths are validated.

- `probe_gap` arrives through `receipt --file` (the assessor path). `validate_item` refuses anything
  that is not a list of integers ≥ 1 — **including `True`**, which is an `int` in Python and would
  otherwise ride an append-only receipt as a silent `1`.
- `rate` has **no** `--probe-gap` flag, on purpose: `rate` is the self-graded path where there is no
  independent grader to notice a probe gap, and a hand-typed one would be an unmeasured claim.
- `edit-node` refuses a blank probe, an empty rubric, a non-array `--rubric-json`, a non-string
  criterion, the capstone, an unknown node, a corrupt node, and a call that changes nothing. Each is
  pinned by a check.

## Q6 · Does its LABEL survive contact with a reader?

Three rules, applied.

1. **Two different denominators may never share a key name.** The node count and the criterion list
   are `notes` (prose, unit named inline) and `probe_gaps` (the list). No key called `n`.
2. **A provenance field must be computed, never asserted.** `kind` distinguishes `unrequested` (the
   engine's own regex), `assessor-flagged` (a reader's judgment during a real grading) and
   `no-rubric` (a structural fact). A user weighing whether to trust an entry needs to know which
   produced it, and neither can claim the other's authority. `receipts_under_previous` is counted
   from the receipt log at edit time, never supplied.
3. **A mean hides its own direction.** Not applicable — nothing here is averaged.

**And the label that needed the most care:** `probe_gap` on a receipt sits beside `grade`, and a
careless reader could take it as a correction to the grade. The assessor spec, the engine comment
and the CHANGELOG all state the same sentence — *it does not move the grade* — and the selftest
pins it: a `partial` with `probe_gap: [2]` stays `partial`/`hard`.

## §5.5 · If the number is an INSTRUMENT, test the instrument

`probe_rubric_gaps` **ranks nothing and certifies nothing** — it emits per-criterion findings a human
verifies. So the monotonicity gate does not apply in its strict form. What does apply is the
property an authoring warning lives or dies by, and it is tested directly:

> **A repaired probe must stop warning.**

Both directions are pinned, and the "silent" half was mutation-tested by *introducing* the false
positive rather than by breaking the detector (§4.5's absence-check rule):

```
probe: "What component distributes traffic across replicas?"
rubric criterion 2: "connects it to horizontal scaling"          -> FLAGGED

probe: "...and what does that buy you as you add machines?"
same rubric                                                       -> SILENT
```

**Measured behaviour on real data, stated rather than rounded:** over the same 60 non-capstone
nodes, the scan flags **21 (35%)** and catches **7 of the 8** cases independently confirmed by the
assessor's own receipt notes. The miss is `cap-theorem`, whose probe ends *"and why can't you escape
it?"* — an explicit `why` silences every family, which is the rule that stops the check flagging
criteria such a probe plainly invited. **Recall was traded for believability, deliberately**, and
the trade is recorded here so a later release can revisit it with evidence rather than taste.

Hand-auditing the 21: roughly 16 are clear, 4 borderline, 1 (`nexttoken-sufficient`) probably wrong.
That is a warning, not a verdict, and it names the criterion so the author can disagree in seconds.

---

## What this audit changed

Nothing in the numbers — because the audit was run against the design *before* the rate got built.
The finding it produced is the absence: **the curriculum-health percentage that would have been the
natural headline of this release does not exist**, because it could not answer Q3 or survive Q2, and
a percentage laundering a heuristic is precisely the shape of every bug in this file's table.
